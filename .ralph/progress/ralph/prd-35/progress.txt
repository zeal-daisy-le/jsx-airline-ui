Issue #16 — Traveller details step (2026-05-22)

Implemented the traveller details booking step at `/booking/details`. Extended `stores/bookingStore.ts` by adding `nationality` to the `TravelerInfo` interface and introducing a new `ContactDetails` type (`{ email, phone }`) with a corresponding `contactDetails` store field and `setContactDetails` action — contact details are persisted to sessionStorage but never server-logged. Created the BFF `POST /api/booking/details` endpoint (`pages/api/booking/details.ts`) with Zod validation on all passenger and contact fields; the endpoint stubs the Navitaire session-update call (pending issue #5) and never logs document numbers. Built the full multi-passenger form in `pages/booking/details.tsx` using React Hook Form + Zod (`mode: "onBlur"` for inline per-field validation) with `useFieldArray`-style indexed registration; one fieldset is rendered per passenger (adult/child/infant) with fields for first name, last name, date of birth, document type (passport/national ID radio), document number, and nationality, plus a shared contact details fieldset. On mount the page fetches `/api/auth/me` and pre-fills the first passenger's name and the contact email from the logged-in user profile if those fields are currently empty. On submit the BFF is called via `withRetry`, then `setTravelerInfo` and `setContactDetails` are saved to the store, GA4 `booking_step_completed` fires, and the user is navigated to `/booking/bags`. All inputs have explicit `<label>` elements, `aria-required`, `aria-describedby` wired to error messages, and error messages use `role="alert"`. Added 32 Vitest tests (BFF validation, page rendering, multi-passenger layout, auth pre-fill, store pre-fill, blur validation, successful submit, BFF error recovery, GA4 events, accessibility). All 308 tests pass.

Issue #17 — Bags selection step (2026-05-26)

Implemented the bags selection booking step at `/booking/bags`. Created the BFF `GET /api/booking/bags` endpoint that returns mock bag options (0/1/2 checked bags with prices $0/$30/$55) with `BagOption` type export, and `POST /api/booking/bags` with Zod validation on the `selections` array (passengerIndex + checkedBags 0–2, max 9 entries) that stubs the Navitaire session-update call (pending issue #5). Replaced the stub `pages/booking/bags.tsx` with a full implementation: per-passenger `<fieldset>` sections with radio-button option cards styled to highlight the selected option, a real-time running total panel with `aria-live="polite"`, loading skeletons (aria-hidden) while bag options load, and inline error recovery (alert + "Try again" button) when the GET fails — `showToast` is called and the Continue button remains accessible so users can skip bags entirely. On submit, `withRetry` wraps the POST to `/api/booking/bags`, and on success `setBagSelections` saves to the Zustand store, GA4 `booking_step_completed` fires, and the user navigates to `/booking/seats`. Store pre-fill restores previous selections on back-navigation. Established the pattern that `withRetry` is for *submit* mutations only — data loading uses a plain `fetch` with a manual UI retry button to avoid blocking the UI with backoff delays. Added 34 Vitest tests (BFF GET/POST validation, page rendering, multiple passengers, running total, pre-fill, zero-bag submit, successful submission, BFF error recovery, load error recovery, GA4 events, accessibility). All 373 tests pass.
